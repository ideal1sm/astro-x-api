## Важно: фронтенда в проекте нет

В этом репозитории нет frontend-приложения.

Запрещено:
- создавать frontend-страницы;
- создавать React/Vue/JS-компоненты;
- менять frontend routes;
- реализовывать верстку;
- добавлять CSS для сайта;
- делать клиентскую логику.

Нужно делать только:
- backend API;
- database migrations;
- models;
- services;
- controllers;
- requests;
- resources;
- admin panel;
- notifications;
- swagger/openapi;
- tests.

Если задача из PDF звучит как frontend-задача, нужно:
- не реализовывать frontend;
- описать backend/API contract;
- обновить swagger/openapi;
- при необходимости создать backend endpoint или поля для фронта;
- в отчёте явно написать, что frontend-реализация вне scope.

## Реализация

При реализации:

- придерживайся текущего code style;
- придерживайся текущей архитектуры;
- используй существующие сервисы, ресурсы, request-классы и паттерны проекта;
- не создавай дублирующий код без необходимости;
- не реализовывай задачи из других md-файлов.

Если в проекте уже есть аналогичная реализация:
- переиспользуй её;
- расширяй её;
- не создавай альтернативную.

---

## Работа с БД

Если нужны изменения схемы:

- создавать новые миграции;
- не редактировать старые миграции;
- сохранять обратную совместимость;
- не ломать существующие данные.

---

## Работа с API

Если задача затрагивает API:

Обязательно:
- routes;
- controller;
- FormRequest;
- Resource;
- validation;
- обработка ошибок;
- авторизация, если требуется;
- существующий envelope response проекта.

Не придумывать новый формат ответа.

---

## Работа с админкой

Если задача затрагивает админку:

- использовать существующий admin stack;
- не создавать новую админку;
- не делать frontend сайта.

Сохранять разделение:
- Astro-x;
- Мёд;
- Общее.

Если задача относится к заказам магазина:
- использовать раздел Мёд.

Если задача относится к пользователям:
- использовать общий раздел.

---

## Работа с уведомлениями
