# Email-уведомления о новых заказах

**Приоритет:** P1

## Контекст

Блок ТЗ: после оформления заказа администратор должен получать письмо с полным составом заказа и крупным превью товара.

## Что найдено в проекте

- В проекте есть только общая mail-конфигурация Laravel: `config/mail.php`.
- Доменных mailable/notification для заказов нет.
- Существующая `app/Notifications/VerifyEmailNotification.php` относится только к email verification.
- Данных заказа для email пока недостаточно: нет платёжных и расширенных delivery/contact полей.

## Что нужно сделать

1. Спроектировать доменное событие создания заказа и триггер отправки email.
2. Создать шаблон письма для менеджера.
3. Определить список адресатов через env/config.
4. Вывести в письме все бизнес-значимые поля из ТЗ.
5. Решить, отправлять письмо сразу после создания заказа или разделить письмо о создании и письмо об успешной оплате.

## Backend

- Добавить mail config для адресов менеджеров/магазина.
- Добавить Mailable или Notification под новый заказ.
- Отправку привязать к событию создания заказа и при необходимости к очереди.
- Следить, чтобы письмо было устойчиво к отсутствию фото/артикула.

## Admin

- В теле письма должна быть ссылка на заказ в Filament.
- Может потребоваться helper для генерации admin URL.

## Frontend

- Frontend вне репозитория.
- Дополнительных изменений на фронте не требуется, если все данные уже приходят в checkout payload.

## Database

- Отдельные таблицы не обязательны, если не нужен журнал уведомлений.
- При необходимости логирования можно завести audit/event table отдельной задачей.

## API

- Прямых API endpoints не требует.
- Косвенно зависит от полноты данных, сохраняемых при создании заказа.

## Swagger/OpenAPI

- Изменения не обязательны, если не появляются новые endpoints.
- В документации задачи зафиксировать, что email зависит от расширенного заказа.

## Notifications

- Email должен включать:
  - номер и дату заказа;
  - клиента;
  - товары;
  - фото;
  - сумму;
  - оплату;
  - доставку;
  - комментарий;
  - ссылку на заказ в админке.

## Tests

- Отправка письма при создании заказа.
- Корректный получатель.
- Наличие ключевых полей в шаблоне письма.
- Корректная работа без изображения товара.

## Acceptance criteria

- После создания заказа менеджер получает email.
- В письме есть все ключевые данные для обработки заказа.
- Ссылка на заказ в админке рабочая.

## Важные ограничения

- Не слать письмо с неполными данными, если критичные поля заказа ещё не сохраняются.
- Не вшивать email-адреса администраторов в код.

## Notes

- Письмо отправляется после успешного создания заказа и успешной инициализации платежа ЮKassa. Если создание платежа откатывает заказ, email не уходит.
- Отдельное письмо о подтверждённой оплате (`payment.succeeded`) в эту задачу не добавлялось; в текущем письме менеджер видит актуальный `payment_status` на момент оформления.
- Email-адреса менеджеров конфигурируются через `SHOP_ORDER_NOTIFICATION_EMAILS`, отправку можно отключить через `SHOP_ORDER_EMAIL_NOTIFICATIONS_ENABLED`.
- Ошибка отправки письма логируется и не ломает checkout.
- Автотесты и `pint` в текущем окружении не запускаются из-за отсутствующего PHP extension `mbstring`.
