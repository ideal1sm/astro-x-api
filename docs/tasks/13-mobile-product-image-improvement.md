# Улучшение фото товара в мобильной карточке

**Приоритет:** P2

## Контекст

Блок ТЗ: увеличить визуальную высоту и удобство просмотра фото товара на мобильной карточке.

## Что найдено в проекте

- Storefront-карточка товара в репозитории не найдена.
- Backend API уже отдаёт список изображений товара магазина: `app/Http/Api/Resources/ShopProductFullResource.php`, `ShopProductShortResource.php`.
- Изображения хранятся отдельно в `shop_product_images`.

## Что нужно сделать

1. Зафиксировать задачу как внешнюю frontend-задачу.
2. Проверить, хватает ли текущих API данных для мобильной галереи.
3. При необходимости расширить API данными для удобного первичного preview.

## Backend

- Возможно добавить явное поле `primary_image` или сортировку изображений, если фронту это нужно.
- Проверить качество и доступность изображений через storage URL.

## Admin

- Косвенно связано с качеством исходных фото и порядком изображений в товаре.

## Frontend

- Frontend вне репозитория.
- Нужно:
  - увеличить фото-блок на mobile;
  - сохранить пропорции;
  - не ухудшать качество;
  - при необходимости добавить lightbox/zoom.

## Database

- Новые таблицы не требуются.
- Может потребоваться поле порядка/primary image, если его нет и это подтверждено фронтом.

## API

- Возможно расширение product schema полем главного изображения или сортировки.

## Swagger/OpenAPI

- Обновить product schema, если появятся новые image fields.

## Notifications

- Не относится.

## Tests

- API товара возвращает предсказуемый набор изображений.
- При добавлении `primary_image` проверить его наличие.

## Acceptance criteria

- Для фронта задокументировано, какие данные о фото доступны.
- Если API расширялся, данные достаточны для мобильной галереи.

## Важные ограничения

- Не пытаться верстать storefront в этом репозитории без подтверждения архитектуры.
