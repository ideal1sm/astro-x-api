# Правила покупки, оплаты, доставки и возврата

**Приоритет:** P2

## Контекст

Блок ТЗ: магазин должен иметь отдельные информационные страницы для покупателей.

## Что найдено в проекте

- В репозитории нет storefront-страниц магазина.
- В `routes/web.php` отсутствует информационный раздел.
- Админ-модуля для управления контентными страницами не найдено.

## Что нужно сделать

1. Определить источник контента и место размещения страниц.
2. Разбить на отдельные страницы:
  - правила покупки;
  - оплата;
  - доставка;
  - возврат и обмен;
  - гарантия/FAQ при необходимости.
3. Зафиксировать обязательные места размещения ссылок.
4. Если страницы должны управляться из админки, вынести это как отдельный subtask после подтверждения архитектуры.

## Backend

- Если страницы отдаются Laravel, добавить routes/views.
- Если storefront внешний, backend не является основным местом изменений.

## Admin

- Базово не требуется.
- Если контент нужен редактируемый, это отдельная задача на CMS-like сущности.

## Frontend

- Frontend вне репозитория.
- Нужно реализовать страницы и ссылки:
  - в футере;
  - на checkout;
  - при необходимости на карточке товара и в help-разделе.

## Database

- Не требуется без отдельного контентного модуля.

## API

- Не обязателен.

## Swagger/OpenAPI

- Не обязателен.

## Notifications

- Не относится.

## Tests

- Проверка доступности страниц.
- Проверка ссылок из целевых зон интерфейса.

## Acceptance criteria

- Покупатель может открыть информационные страницы до оформления заказа.
- Ссылки на страницы размещены в согласованных местах.

## Важные ограничения

- Не проектировать полноценный CMS-блок без подтверждённой необходимости.
- Контент должен быть предоставлен бизнесом.
