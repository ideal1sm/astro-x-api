# Политика конфиденциальности

**Приоритет:** P1

## Контекст

Блок ТЗ: на сайте должна быть опубликована Политика конфиденциальности и ссылки на неё во всех формах.

## Что найдено в проекте

- Пользовательский storefront в репозитории не найден.
- В `routes/web.php` есть только дефолтный `welcome`.
- CMS/контентный модуль для статических страниц в проекте не найден.

## Что нужно сделать

1. Определить, где в текущей архитектуре будут жить юридические страницы:
  - во внешнем frontend;
  - в Laravel `web.php` + Blade;
  - в отдельном CMS-слое, если он существует вне репозитория.
2. Подготовить задачу как backend/frontend contract, если storefront внешний.
3. Зафиксировать URL страницы и обязательные места размещения ссылок.

## Backend

- Если страницы обслуживает Laravel, добавить route/controller/view или иной agreed mechanism.
- Если frontend внешний, backend может только хранить/отдавать контент через API при необходимости.

## Admin

- По желанию можно предусмотреть редактирование юридических текстов из админки, но это не обязательно для первой итерации и должно быть отдельным решением.

## Frontend

- Frontend вне репозитория.
- Нужно реализовать отдельную страницу политики и ссылки на неё:
  - в футере;
  - в checkout;
  - во всех формах с персональными данными.

## Database

- Не требуется, если текст страницы хранится в коде/внешнем frontend.
- Если нужен управляемый контент, это отдельная задача на таблицы CMS.

## API

- Не обязателен, если страница статическая.

## Swagger/OpenAPI

- Не обязателен.

## Notifications

- Не относится.

## Tests

- Проверка доступности страницы.
- Проверка корректных ссылок из форм и футера.
- Для backend-only части: HTTP 200 и корректный route.

## Acceptance criteria

- Страница политики существует и открывается.
- Ссылки на политику доступны в checkout и других формах.

## Важные ограничения

- Не придумывать CMS-архитектуру без подтверждения.
- Текст политики должен быть предоставлен бизнесом/юристом, если он не хранится в проекте.
