# Страница 404

**Приоритет:** P2

## Контекст

Блок ТЗ: нужна стилизованная 404-страница магазина с корректным HTTP-статусом.

## Что найдено в проекте

- Веб-часть в репозитории минимальная: `routes/web.php`, `resources/views/welcome.blade.php`.
- Кастомной 404-страницы в проекте не найдено.
- Для API 404 уже обрабатываются отдельно через JSON contracts.

## Что нужно сделать

1. Определить, где живёт пользовательская 404:
  - во внешнем storefront;
  - в Laravel web-layer.
2. Если storefront внешний, зафиксировать это как фронтовую задачу.
3. Если Laravel должен отдавать страницу, добавить кастомную 404-view.
4. Убедиться, что backend по web-route отдаёт HTTP 404, а не только красивую страницу.

## Backend

- При необходимости добавить `resources/views/errors/404.blade.php` и проверить handler.

## Admin

- Не относится.

## Frontend

- Frontend вне репозитория.
- Должен реализовать текст, CTA-кнопки и адаптивность страницы.

## Database

- Не требуется.

## API

- Не смешивать HTML 404 storefront и JSON 404 API.

## Swagger/OpenAPI

- Не требуется для HTML-страницы.

## Notifications

- Не относится.

## Tests

- HTTP 404 на несуществующем web URL.
- Корректная HTML-страница/маршрут.
- Отдельно убедиться, что API по-прежнему возвращает JSON 404.

## Acceptance criteria

- Пользователь видит понятную 404-страницу.
- Сервер возвращает корректный статус 404.
- API контракты не сломаны.

## Важные ограничения

- Не подменять API 404 HTML-страницей.
- Если storefront внешний, не пытаться реализовать страницу внутри этого repo без подтверждения.
