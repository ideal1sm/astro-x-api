# Страница успешного оформления заказа

**Приоритет:** P2

## Контекст

Блок ТЗ: после оформления заказа пользователь должен увидеть понятную страницу подтверждения с ключевыми данными заказа.

## Что найдено в проекте

- Storefront-страница оформления в репозитории не найдена.
- Текущий `POST /api/v1/shop/orders` возвращает только JSON-ответ API: `app/Http/Api/Controllers/ShopOrderController.php`, `app/Http/Api/Resources/ShopOrderFullResource.php`.
- В ответе пока нет платёжных и расширенных delivery-полей.

## Что нужно сделать

1. Зафиксировать контракт данных, который нужен фронту для success page.
2. Обновить API ответа заказа, чтобы в нём были:
  - номер заказа;
  - итоговая сумма;
  - способ оплаты;
  - статус оплаты;
  - способ доставки;
  - адрес/ПВЗ;
  - сообщение для пользователя.
3. Если success page зависит от платёжного callback, учесть это в задаче по ЮKassa.

## Backend

- Расширить response заказа нужными полями.
- При необходимости добавить отдельный endpoint получения публичных данных заказа после checkout/payment return.

## Admin

- Не относится напрямую.

## Frontend

- Frontend вне репозитория.
- Нужно реализовать success page и использовать данные из API/redirect flow.

## Database

- Зависит от задач по доставке и оплате.

## API

- Изменить response `POST /api/v1/shop/orders`.
- При необходимости добавить public-safe endpoint для получения подтверждения заказа после редиректа.

## Swagger/OpenAPI

- Обновить response schema заказа и checkout flow.

## Notifications

- Текст success page должен быть согласован с email/платёжным сценарием, чтобы не вводить пользователя в заблуждение.

## Tests

- В response создания заказа есть все данные для success page.
- При сценарии с оплатой после редиректа endpoint корректно отдаёт заказ.

## Acceptance criteria

- Фронт получает достаточно данных для страницы подтверждения заказа.
- Сообщение пользователю соответствует фактическому статусу оплаты.

## Важные ограничения

- Не считать заказ оплаченным только по факту создания.
- Не раскрывать лишние данные по заказу в публичном endpoint без безопасного механизма доступа.
