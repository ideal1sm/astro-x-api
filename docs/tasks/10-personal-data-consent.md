# Согласие на обработку персональных данных

**Приоритет:** P1

## Контекст

Блок ТЗ: во всех формах сайта нужен обязательный чекбокс согласия. Для backend этого репозитория критичен как минимум checkout.

## Что найдено в проекте

- Frontend-формы storefront в репозитории не найдены.
- Checkout API пока не требует согласия: `app/Http/Api/Requests/CreateShopOrderRequest.php`.
- Юридические страницы в repo не реализованы.

## Что нужно сделать

1. Добавить обязательное согласие в создание магазинного заказа.
2. Зафиксировать требования для всех остальных форм сайта как frontend task / integration note.
3. Определить формат хранения согласия в заказе:
  - bool-флаг;
  - timestamp;
  - текстовая версия/версия документа, если это нужно юридически.
4. Согласовать ссылки на страницу политики и страницу согласия.

## Backend

- Обновить request validation checkout.
- Сохранять факт согласия в заказе или отдельном аудите.
- Возвращать понятную validation error без согласия.

## Admin

- Показать в заказе, что согласие было получено.
- При необходимости хранить дату/время согласия.

## Frontend

- Frontend вне репозитория.
- Для всех форм с PII frontend должен:
  - показывать неотмеченный checkbox;
  - блокировать отправку без согласия;
  - рендерить ссылки на политику и согласие.

## Database

- Новая миграция для `shop_orders` с полями согласия, если согласие хранится на заказе.

## API

- Обновить `POST /api/v1/shop/orders` новым обязательным полем.

## Swagger/OpenAPI

- Описать обязательное поле согласия и возможные validation errors.

## Notifications

- Не относится напрямую.

## Tests

- Ошибка при отсутствии согласия.
- Успех при передаче согласия.
- Сохранение признака согласия в БД.

## Acceptance criteria

- Заказ не создаётся без согласия.
- Факт согласия сохраняется и виден менеджеру.
- Для внешнего фронта зафиксирован единый contract для всех форм.

## Важные ограничения

- Не отмечать чекбокс по умолчанию.
- Не ограничиваться только frontend-валидацией, backend тоже обязан проверять согласие.
