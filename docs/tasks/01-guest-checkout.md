# Гостевое оформление заказа

**Приоритет:** P1

## Статус реализации

Реализовано.

## Что фактически сделано

- `POST /api/v1/shop/orders` открыт для гостя.
- Сценарий создания заказа работает и для гостя, и для авторизованного пользователя.
- В `shop_orders` добавлены и сохраняются:
  - `customer_name`;
  - `customer_phone`;
  - `customer_email`;
  - `personal_data_consent_at`.
- `user_id` в заказе магазина переведён в nullable:
  - для гостя сохраняется `null`;
  - для авторизованного пользователя сохраняется общий `users.id`.
- Валидация checkout обновлена:
  - обязательны имя, телефон, email;
  - обязательно согласие на обработку персональных данных.
- `GET /api/v1/shop/orders` и `GET /api/v1/shop/orders/{id}` оставлены под авторизацией.
- В админке заказа добавлен блок покупателя:
  - имя;
  - телефон;
  - email;
  - связанный аккаунт или пометка гостевого заказа.
- `openapi.json` синхронизирован под публичный guest checkout contract.
- Добавлены feature-тесты на guest/auth checkout и validation.

- Новая схема доставки не реализуется в рамках этой задачи.

## Контекст

Блок ТЗ: оформление заказа без авторизации. Сейчас магазинный заказ можно создать только под `auth:sanctum`, поэтому checkout не готов к запуску.

## Что найдено в проекте

- Маршрут создания магазинного заказа закрыт авторизацией: `routes/api.php`.
- Контроллер: `app/Http/Api/Controllers/ShopOrderController.php`.
- Валидация: `app/Http/Api/Requests/CreateShopOrderRequest.php`.
- Сервис создания: `app/Services/CreateShopOrderService.php`.
- Модель заказа: `app/Models/ShopOrder.php`.
- Текущая таблица `shop_orders` требует `user_id` (`database/migrations/2026_04_13_000003_create_shop_orders_table.php`).
- Общие пользователи и адреса: `app/Models/User.php`, `app/Models/UserAddress.php`.
- OpenAPI уже описывает shop-orders, но пока под текущую авторизованную модель: `openapi.json`.

## Что нужно сделать

1. Спроектировать guest-checkout для `POST /api/v1/shop/orders` без обязательного логина.
2. Разделить создание заказа магазина на два сценария: гость и авторизованный пользователь.
3. Уточнить, будет ли заказ привязываться к `user_id`, если пользователь авторизован, и оставаться `null` для гостя.
4. Добавить в заказ обязательные контактные поля из ТЗ: имя, телефон, email.
5. Добавить поле комментария к заказу.
6. Добавить обязательный флаг согласия с политикой и обработкой персональных данных.
7. Проверить, не нужны ли отдельные DTO/resource-представления для ответа гостю.

- Гость может создать заказ без регистрации.

- Авторизованный пользователь по-прежнему может создать заказ.
- Ответы API соответствуют текущему envelope.

## Важные ограничения

- Не переводить магазин на отдельную таблицу пользователей.
- Не ломать текущие личные кабинеты и адреса пользователя.
- Не использовать таблицы `orders` / `order_items` Astro-x для магазина.
